# ARMORED KOALA 2 (AK2) DEMO

コアラの頭を持つ戦闘ロボットを操作し、廃工場「コアラ重工 第3工場」から脱出する TPS 高速メカアクションシューティング。Three.js（0.186.1）+ TypeScript + Vite で実装しています。仕様書原文は [docs/SPEC.md](docs/SPEC.md)、モジュール契約は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)、ステージ設計記録は [docs/STAGE.md](docs/STAGE.md) です。

## 1. 起動手順

要件: Node.js 22 系（開発時 v22.22.0 / npm 10.9.4）。依存関係は `package.json` で完全固定し、`package-lock.json` を同梱しています。実行時に外部 API・CDN・画像・モデル・音源は一切取得しません（素材は全てコードで生成）。

```bash
npm ci
npm run build                                   # 型検査 + 本番ビルド（dist/）
npm run dev -- --host 0.0.0.0 --port 5173       # 開発サーバー
```

ブラウザーで `http://localhost:5173/` を開くと格納庫が表示されます。確認環境は macOS + Chromium 系ブラウザー、表示領域 1280×720 以上（ウィンドウのリサイズに追従します）。

- `?seed=<32bit 符号なし整数>` でゲーム進行の乱数シードを指定できます（未指定時 20260908）。視覚効果の乱数は別系列です。
- 検証用: `npm test`（vitest、全テスト）、`npm run stage:verify`（ステージ規模の自動検証のみ）。
- 開発サーバー限定の検証フック: `http://localhost:5173/?devhook` で開くと `window.__AK2_DEV`（`launchNoLock()` / `step(frames, input)` など）が使えます。ポインターロックなしで出撃できるため自動検証に使いました。`import.meta.env.DEV` で切られ、本番ビルド（`dist/`）には含まれません。

## 2. 操作方法

| 操作 | 入力 | 挙動（2脚基準） | EN |
|---|---|---|---|
| 移動 | W/A/S/D | 10 m/s（カメラ水平方向基準、斜めでも速度は増えない） | 0 |
| 視点・照準 | マウス移動 | TPS カメラ旋回（ポインターロック中） | 0 |
| ジャンプ | Space（接地中に押す） | 上向き初速 10 m/s | 0 |
| 飛行 | Space を 0.20 秒以上長押し | 上昇 8 m/s、空中水平 16 m/s。離すか EN 0 で重力運動へ | 20 EN/秒 |
| グライド切替 | Shift を 1 回押す | 地上 22 m/s で移動を継続（押し続け不要。入力を離しても最後の方向を保持） | 0 |
| ブレーキ | 左 Ctrl（押している間） | グライド解除、慣性を伴って減速 | 0 |
| クイックブースト | Q を 1 回押す | 初速 80 m/s で 0.15 秒噴射 → 自動でグライドへ移行（0.60 秒で 22 m/s へ減速）。1.00 秒に 1 回 | 発動時 36 EN |
| 射撃 | マウス左ボタン | 押している間、武器の射撃間隔で発射 | 武器による |
| 武器切替 | 1 / 2 / 3 | マシンガン / ビーム / ハンドミサイル（残弾・次回発射時刻は保持） | 0 |
| 一時停止 | Esc | ポインターロック解除と一時停止 | 0 |

- QB は「離された状態から押された瞬間」だけ発動します。押し続けても、OS のキーリピートでも再発動しません。停止は左 Ctrl か Shift でのグライド解除です。
- **FCS（Flight Control System）**: 画面中央の円に敵の当たり判定中心を保つとロックが自動で進み、完了後はマシンガンの偏差＋重力落下、ミサイルの偏差を FCS が自動補正して実際の射出方向に適用します。中央の照準を補正マーカー（◇）へ手動で合わせる必要はありません。ビームは発射時の現在位置へ即時命中します。ミサイルはロック完了時のみ発射できます。
- 4脚は水平移動速度 ×0.80（通常 8 / グライド 17.6 / 空中 12.8 / QB 64 m/s）、EN 回復 ×0.75、ロック速度 ×1.50。ジャンプ・上昇・重力には倍率がかかりません。

HUD: 中央にロック円（半径 = FCS の判定円そのもの）と照準、対象マーカー（[ ] ）、補正照準マーカー（◇「補正中」/「解なし」/「補正 初期偏差」）、左に武器と残弾、右に EN と移動モード・QB 可否・残り冷却時間、下に HP、上に区画名・次の目標・制御砲台 n/6・開放済み隔壁・最終ゲート状態。被弾方向は円の周りの赤いくさび、敵の射撃予告は「!」マーカーと砲口の明滅で示します。操作説明は格納庫と一時停止画面から参照できます。

## 3. 機体構成（出撃前に選択、3×3×2 = 18 通り）

| FCS | ロック円半径 | 基本ロック所要時間 |
|---|---|---|
| 広範囲 | 0.30D | 1.20 s |
| 中範囲（初期） | 0.20D | 0.80 s |
| 狭範囲 | 0.10D | 0.40 s |

| ジェネレーター | 最大 EN | 基本回復率 |
|---|---|---|
| 大容量 | 180 | 10 EN/s |
| 均衡（初期） | 120 | 15 EN/s |
| 高回復 | 90 | 20 EN/s |

| 脚部 | 水平速度 | EN 回復 | ロック速度 |
|---|---|---|---|
| 2脚（初期） | ×1.00 | ×1.00 | ×1.00 |
| 4脚 | ×0.80 | ×0.75 | ×1.50 |

実効値 = ジェネレーター回復率 × 脚部回復倍率、ロック所要時間 = FCS 基本時間 ÷ 脚部ロック速度倍率（例: 中範囲・均衡・4脚 → 120 EN / 11.25 EN/s / 0.533 s）。格納庫では選択中の部品、長所短所、実効値、3D モデル（2脚/4脚で脚が変わる）を表示します。数値は全て `src/params.ts` の定義をゲームロジックと共用しています。

武器: マシンガン（12 dmg / 0.10 s / 300 発 / 初速 100 m/s、重力 18 m/s²、寿命 2 s）、ビーム（40 dmg / 0.25 s / 8 EN / 射程 120 m 即時命中）、ハンドミサイル（180 dmg / 1.00 s / 12 発 / 45 m/s、旋回 120°/s、寿命 4 s、ロック必須）。プレイヤーの弾は自機速度を継承しません。

## 4. アーキテクチャ

```
src/params.ts        全パラメーター（唯一の定義場所）
src/types.ts         共有型（StageData, Snapshot, HudView, SimEvent ...）
src/sim/             DOM/Three.js 非依存のシミュレーション（vitest の node 環境で丸ごと実行）
  game.ts            統括: 状態遷移、1/120 s 固定刻み＋イベント時刻分割、目標進行、スナップショット
  player.ts          移動・EN・QB・グライド・ジャンプ・飛行・衝突
  fcs.ts             ロック（候補条件・進捗）と武器ごとの射撃解
  ballistics.ts      §4.3 の 4 次方程式（区間分離＋二分法＋ニュートン、重根・端点対応）と線形偏差解
  weapons.ts         発射成立判定・消費・ShotRecord
  projectiles.ts     マシンガン弾（解析的放物線）、誘導ミサイル、敵弾。移動区間の掃引衝突
  enemy.ts / nav.ts  警備ロボット・固定砲台の AI、A* 経路探索グリッド
  collision.ts/geom.ts AABB ワールド（XZ グリッド広域判定）、レイ・掃引球・ボックス移動
  camera.ts          TPS カメラ（壁めり込み回避）と画面投影（ロック円判定に使用）
src/stage/           ステージ定義（stageData.ts）と規模検証器（verify.ts）
src/render/          Three.js 描画（機体・敵・ステージ・弾体・効果）
src/ui/              HUD・格納庫・一時停止/結果画面（HTML/CSS）
src/main.ts          結線、ポインターロック、描画ループ、ベンチ API
```

- シミュレーションは実時間を 1/120 s 以下の刻みに分割し、QB 噴射終了・EN 回復開始・飛行 EN 枯渇・射撃時刻・敵の射撃時刻でさらに分割します。射撃はその時刻の機体・銃口・対象の状態でロックを再検証してから解を計算し、生成した弾は残りの区間だけ進めます。30/60/120 fps で結果が一致することをテストで確認しています。
- 一時停止中（Esc、ポインターロック喪失、フォーカス喪失、タブ非表示）は経過時間・弾体・敵タイマー・QB・ロック・ミサイル観測の全てが止まり、復帰時にまとめて加算しません。復帰後は入力状態を解除するので Q を押し直す必要があります。
- 敵弾はプレイヤーの AABB との移動区間衝突でのみダメージを与え、ステージ遮蔽物で止まります。時間だけで HP を減らす処理はありません。
- `window.AK2_BENCH.getSnapshot()` は §10 の構造でコピーを返す読み取り専用 API です（`src/bench.ts`）。

### 6.3 敵の攻撃（tests/enemy.test.ts, tests/nav.test.ts, tests/exposure.test.ts）

- 初動: 警備ロボットは射線取得から 0.5000 s、砲台は 0.7000 s に初弾。バースト: 警備 0.50/0.62/0.74 → 1.70/1.82/1.94 s、砲台 0.70/0.95 → 2.30/2.55 s（周期に予告を追加しない）。
- 偏差射撃: 10 m/s で横移動するプレイヤー（40 m）に対し、迎撃時刻 0.615 s の予測位置へ 0.0014° の誤差で射撃（ばらつき ≤ 0.5°）。
- 遮蔽: 遮蔽中は発射せず、再露出時は max(次バースト時刻, 再露出 + 予告) で再開（初回待ち時間をやり直さない）。8 s で記憶失効。射線を失った警備ロボットは 0.5 s 以内に最後の確認位置へ経路探索で移動。60 m 以内（経路距離）の味方へ位置を共有。
- 移動: >55 m で 8 m/s 接近、25〜55 m で 6 m/s 側方移動、<15 m で 8 m/s 後退。カメラの向きに依存しない（EnemyManager にカメラの概念がない）。
- **露出時の危険性**: 平地で 35〜50 m の警備 2 体＋砲台 1 体、静止 HP1000 → 初弾 0.500 s、**7.86 s で撃破**（45 発命中、通常の AI・弾体・当たり判定のみ）。壁の陰では被弾 0。

### 6.4 正規経路の自動走行（tests/routePlaythrough.test.ts）

### 6.5 進行・状態管理（tests/game.test.ts）

制御砲台の破壊 → 対応する隔壁のコライダー消滅 → 6 体で最終ゲート開放 → 脱出領域でクリア。未開放ではゲート接触・脱出領域侵入でクリアしない。同一更新でクリアと HP0 が成立した場合は失敗優先。落下失敗。再出撃で位置・HP・EN・残弾・敵 45 体・隔壁・ゲート・射撃履歴・QB 回数・ロック・経過時間が初期化され、ID は同一。一時停止中は時間・位置・EN・QB 噴射残り・弾・敵射撃数が不変で、復帰後に一括加算されない。スナップショットはコピー（編集しても状態不変、NaN/Infinity なし）。30/60/120 fps で位置と EN が一致。

## 7. 未確認項目・既知の問題

- ポインターロックの**取得成功**経路と、実際のマウス・キーボードによる長時間プレイ（10〜20 分の所要時間目安）は自動化環境では確認できていません。ロック取得後の処理はコード上で確認し、取得失敗経路のみ実機で確認しました。
- ステージ全体の通過は検証器（自由飛行の下限モデル）と、`Game` の物理で経路を自動走行するテスト（tests/routePlaythrough.test.ts）で確認しています。人間による通しプレイの所要時間は未計測です。
- 隔壁は開放時に 0.35 秒かけて床へ沈む演出があり、コライダーはその瞬間に消えます（通過可能になるのが見た目より僅かに早い）。
- ミサイルは対象以外の敵に直撃した場合もその敵にダメージを与えます（直接命中した対象にのみダメージ、という仕様の範囲内）。
- 格納庫の長所短所の文章（`PART_DESCRIPTIONS`）は数値を文字列として含みます。現在の値と一致していますが、パラメーター変更時は文章も更新が必要です（実効値の表は `computeEffectiveStats` から計算）。
- 実ステージで全 45 体を相手にした場合の 1 フレームあたりの `Game.advance` コストは自動走行テストで問題ありませんでしたが、低性能環境での 60 fps 維持は未計測です。
- `kind: 'target'`（試験用標的）は試験ステージ専用で、本編ステージには存在しません。
