# ステージ骨格 (STAGE_BLUEPRINT)

> **この文書は骨格(区画の作り込み前)の設計書で、§10 の敵の仮配置は骨格時点の値。現在の配置は docs/STAGE.md。**
> 区画の作り込みは完了しており、現在の敵の初期配置・区画表・経路座標・検証結果は `docs/STAGE.md`(`npx tsx tools/stage-report.ts` が生成)、
> 各区画の中身は `src/stage/sectors/Sxx.ts`、骨格のデータは `src/stage/blueprint.ts` を参照する。
> 骨格のままの値(区画bounds・portal・隔壁・昇降・分岐・環状経路・ARENA_CLEAR)は今も有効で、そのまま残してある。
> 陳腐化していた数値・記述(最短経路長、床面積、射線を取る敵数、開始地点の形、decor の数、T03 の高さ、敵の配置が仮という記述など)だけを現在の実測値に直した。

ARMORED KOALA 2 DEMO の廃工場ステージの「骨格」設計書。担当: stage0。次フェーズでは各区画の内部(掩蔽物・設備・敵配置・装飾)を
`src/stage/sectors/Sxx.ts` の中だけで作り込む。ステージ全体の必須要件(SPEC §2.1 / §2.2)は、この骨格ですでに実形状として満たしている。
数値は「実測」と「設計値」を分けて書く。実測は `tools/route-probe.ts`(自前の簡易プローブ)と `src/stage/validate.ts`(stagecheck の厳密検証器)、
`tests/stage-blueprint.test.ts` の出力による。

- 座標: 東 +x / 南 +z / 上 +y。単位 m。プレイヤー当たり判定 1.6×3.0×1.6m(中心は床上 1.5m)。
- 殻: 床スラブ 2m(上面 = floorY)・壁 2m・天井スラブ 2m。区画 bounds は殻を含む外形で、隣接区画は境界面を共有する(境界の壁は両側で計4m厚)。
- 区画は全て単独の閉じた箱(壁は床〜天井の全高、屋根で全面を覆う)。区画間の行き来は portal(開口)だけで、飛行で壁を越えて省略することはできない。

## 12. 区画の作り込みの規約 (骨格時点は「次フェーズ」の規約。作り込み完了後も、区画を変更するときの規約として有効)

1. 編集してよいのは `src/stage/sectors/Sxx.ts` の `build(kit)` の中だけ。殻(床・壁・天井・開口・隔壁)は `StageBuilder` が `build(kit)` の前に作る。
2. 使えるプリミティブ: `box / boxC / fbox / crate / pillar / pipe / platform / catwalk(手すり付き) / pedestal / partition / decor / guard / turret / climbPads`。
   `pipe` は断面が 3m 以下のときだけ円柱の見た目ヒント(cylX/Y/Z)を付け、それより太いものは箱で描画される(衝突は常に外接AABBなので、見た目=衝突を守るため)。
   箱は自区画の bounds 内、portal 前の 6m 四方(開口の高さ範囲)、`ARENA_CLEAR`、`RESERVED`(出撃位置・分岐アンカー・昇降の離陸柱と飛行コリドー)には置けない(例外)。
3. 敵は `kit.guard(x, z, …)` / `kit.turret(x, z, 台座の高さ, { control })`。**区画ごとの数は `ENEMY_BUDGET` を守る**(テストで検証)。制御砲台は `control: 0..5`(B1..B6)で
   S03/S06/S08/S11/S13/S14 に固定。制御砲台は自隔壁へ射線が通る位置に置く(テスト)。警備は箱から 1.1m 以上、砲台は 1.3m 以上離す。
4. 昇降の足場(`kit.climbPads`)と `CLIMB_SPECS` の from/to の周辺(離陸柱・飛行コリドー・2.78m の踏み台の連鎖)は変えない。足場の縁に 0.7m を超える手すりを付けない。
5. 描画負荷: 1区画の箱は数十〜数百が目安。装飾の細部は `kit.decor`(衝突なし、壁面/床面から 0.15m 以内)にする。
6. 内部を変えたら次を順に実行して合格させる:
   ```
   npx vitest run tests/stage-blueprint.test.ts     # 不変条件 + validateStage + 実際のGameでの隔壁/クリア
   npx tsx tools/route-probe.ts --barriers          # 最短経路・昇降の経路距離・分岐長・隔壁の必須性・外周
   npx tsx tools/route-probe.ts --emit              # 障害物で mainRoute/分岐の折れ線が塞がれたら src/stage/routes.ts を再生成
   ```
7. bounds・portal・隔壁・昇降・予算・ARENA_CLEAR・RESERVED(= `blueprint.ts`)を変える必要が出たら、stage0 への要望として報告する。

## 13. 既知の制約・未確認

- 最短経路長は「実行可能な経路(=真の最短の上界)」。2つの独立した実装(route-probe の A*+平滑化と validate.ts)で 2235m / 2149m (骨格時点は 2231m / 2137m)、下限を保守的に見ても 1800m を大きく超える。
  ここでの「実行可能」は、飛行自由・EN無視・全隔壁開放の意味。実際に歩行 + 落下 + 8 回の飛行昇降で走るボットの実走距離は docs/PLAYTHROUGH.md (2359〜2374m)。
  真の最短の厳密な下界は求めていない。
- 昇降は飛行(上昇 8m/s・20EN/秒)で登る想定。降下は落下(下りは 24〜26m。落下ダメージの仕様はない)。降下後に着地して EN が回復できる床が必ずある。
- 敵の配置は骨格時点では仮だった。区画の作り込みで確定し(docs/STAGE.md §5)、検証器の `enemies.spawns` (埋まり・浮き・頭上空きなし 0 件)と敵AIの試験(全警備の到達性・立ち止まり)で確認済み。
- 屋根・壁の見た目(窓・破損・警告灯)は、骨格時点では未作成で decor は 3 点のみだった。区画の作り込みで各区画に装飾を追加済み(衝突なし)。
- 経路の所要時間(10〜20分)は未測定(プレイテストでの調整目安)。
