## 1. 結論

- **6体全て、狙撃位置 (銃口から 77.9〜113.8 m) から マシンガン・ビーム・ミサイルの全てで破壊でき、対応する隔壁 B1〜B6 が開いた** (`objective.openBarrierIds`、`world` の箱が無効化、プレイヤー箱が実際に通り抜けられる)。
  1つのGameで6体を順に破壊すると `controlsDestroyed` が 1〜6 と増え、5体目までは最終ゲートが閉じたまま、6体目で `gateOpen` になりゲートの箱が無効化される (§5)。
- 通常のFCS経路 (ロック取得 → 0.800秒でロック完了 → 補正射撃) だけで撃てた。射撃解は全て `solved`、残差は 1.4e-14 m 以下 (0.01 m の許容に対し)。
  マシンガンは **決着した弾の 100% (20/20) が命中**。ロック完了前の自由射撃 (補正なし) は9発全てが壁・床に当たり1発も標的に届かない (対照実験, §3.2)。
- 必要な弾数: マシンガン 20発命中 (240/12) だが、破壊の瞬間に飛翔中の弾が 6〜11発あり、**実際の消費は 27〜31発** (300発の 9〜10%。6体で 173発 = 58%)。ビーム 6射 (EN 48)。ミサイル 2発命中 (180×2≥240) で、**連射する限り 3〜4発を消費**。
- 所要時間 (配置から破壊まで): マシンガン 3.48〜3.82秒、ビーム 2.07秒、ミサイル 3.51〜4.30秒。
- 遠隔破壊は**過度に理不尽ではなく、むしろ易しい寄り**: マシンガンで立ったまま撃ち切っても被弾は破壊までに 1〜11回 (40〜242 HP。ビームなら 0〜3回)、掩蔽ボットは平均 0〜216 HP、何もせず立ち続けても 12〜57秒は生き残る (§4)。
  制御砲台そのものより、狙撃位置の近くを巡回する警備ロボット (S08 の G17、S11 の G23、S03 の G07/G08/G09) が脅威になる。
- 見つけた問題 (§5): (1) S11 の報告された狙撃候補は T11 から 121.6〜132.1 m でFCS射程 (120 m) の外、S03・S08 の報告候補も 60〜118 m の要件を満たさない/掩蔽にならない
  (2) 砲台から見えないのにロックして一方的に撃てる位置がある (敵の視線判定はプレイヤー中心の1点だけ) (3) マシンガンの弾薬配分。

## 2. 方法

### 2.1 実際のGameで動かす (何を初期条件とし、何を実際に通したか)

- **初期条件 (配置) として行うのは3つだけ**: プレイヤーを狙撃位置に置く (速度0・接地)、プレイヤーHPを 1e9 にする (kill / cover 実行のみ)、視点を砲台へ向ける (`Game.look()` のマウス入力)。位置は初期状態の設定で、以降は `Game.input` / `Game.look()` / `Game.step()` だけ。
  **HP 1e9 は「被弾しても実行が終わらない」ためで、敵の攻撃は弱めていない**。被弾で HP が実際に減ること (`hpEnd = 1e9 - 被ダメージ`、各被弾のダメージは 18 か 40) をテストで確認している。生存時間の実測 (§4.3) は実HP 1000。
- **実際に通した処理**: FCSのロック取得 (`updateFcs`: カメラと銃口の双方から砲台中心が見える・画面の円内・120m以内) → ロック完了 → 射撃時の再検証 → 射撃解の計算 (`computeFireSolution`) →
  弾体 (`stepPlayerProjectiles` の掃引衝突。標的は半径 1.4 m の球) / ビーム (`resolveBeam`) → `damageEnemy` → `updateProgress` (隔壁の箱を無効化)。
  砲台のHP・隔壁・ロック・弾体は直接書き換えていない。
- **他の44体は生きたまま実AIで反撃する** (警戒・射線・偏差射撃・共有・巡回)。イベントは毎 tick `drainEvents()` で回収して計測 (発射数・命中・被弾の撃った敵)。
- ロードアウトは既定 (中範囲FCS・均衡ジェネレーター・2脚。ロック円 0.20D = 144 px @1280×720、ロック所要 0.80秒)。他の17構成は未実施。

### 2.2 狙撃位置の探索 (自動)

1. **立てる床の列挙**: 制御砲台の区画の全ての箱の上面から、4隅が箱に乗り (`World.pointInSolid`)、壁・天井から 0.2 m 以上離れる (`World.overlapAABB`) 点を 2 m 格子で列挙 (3830〜5571 点/区画)。
2. **到達性**: 区画の入口 (隔壁のない portal / b側の入口) から、実際の `World.sweepAABB` で 歩行・ジャンプ (段差 2.5 m 以下)・跳び越え・降下 でつながる集合を求める。歩行で着けない点は歩行到達点からの飛行1回 (上昇 2.5〜16.5 m) で着けるかを判定 (`access = walk / fly`)。
3. **FCS・弾道**: 各点にプレイヤーを立たせ、カメラ位置から砲台中心が画面中央に来るまで yaw/pitch を反復 (実際の `updateCamera` / `playerMuzzlePosition`) し、
   実際の `isLockCandidate` (ロック可)、銃口→砲台中心の距離 60〜118 m、`solveMachinegun` の解の放物線を 1/120 秒刻みで実際の `sweepSphere` と球衝突で辿ってマシンガンが砲台に届くか、ビームの `raycast`、ミサイルの `sweepSphere` (半径 0.25) を評価。
   砲台以外がロック候補に入らない (別の敵を先にロックしない) ことも要求。
4. **反撃と掩蔽**: 砲台が (初期位置から) プレイヤー中心を見つける位置だけを候補にする (反撃を受ける位置)。他の敵に初期位置・巡回経路 (各辺を 6 m おき) から見つかるかを数え、
   近く (1.5〜9 m) に **全ての敵 (砲台・巡回位置を含む) から見えず、中心と左右前後 ±0.7 m の5点が隠れている**、同じ高さの点 (掩蔽点) を探す。
5. **採用位置の選定 (`--pick`)**: 上位候補 (互いに 6 m 以上離し、歩いて着ける位置) と、区画作り込み担当が報告した領域の最良点を、**掩蔽ボットで 5 seed 実走**し、
   全 seed で破壊でき、距離 75〜116 m のうち被ダメージ平均が最小 (同点は破壊が早い方) のものを採用した。
6. **独立した到達性の確認**: 警備ロボット用の歩行グラフ (`nav.ts`: 段差 0.3 m・体幅 2.7 m の保守的な判定) で、区画の歩き始め (床の高さの入口。S08/S13 は +24 のギャラリーから降りた床の警備の足元) → 狙撃位置の近くの開けた床 → 狙撃位置 (プレイヤーの体幅で直進) が通じることを確認 (表の「歩行経路」)。

### 2.3 ボット (簡易。入力は `Game.input` と `Game.look()` だけ)

- **stand**: 狙撃位置に立ったまま。砲台に視点を合わせ続け、ロック完了で撃つ。回避しない。
- **cover**: 掩蔽点から始める。掩蔽点にいる間、発射位置に当たる敵弾 (撃たれたばかりのものを含む) が無くなるまで (最低 0.4秒、最長 3秒) 待って、WASD で発射位置へ歩いて身を出す。
  ロックが完了したら撃つ。**最低3発は撃ってから**、撃たれて 0.2秒たった (=見える) 敵弾が「今の位置に当たる」到達までの時間が (掩蔽点までの歩行時間 + 0.05秒) 以下になるか、被弾したら掩蔽点へ引っ込む。
  射線の通った警備ロボットが 70 m 以内にいれば、その場でロックして撃つ (倒すまで身の出し入れを止める)。
- **idle**: 何も入力しない (実HP 1000)。

### 2.4 指標の定義

- 「ロック取得→完了」: 標的を最初に選択 (取得中) した時刻 → ロック完了の時刻 (`state.lock`)。
- 「標的への発射/命中」: 射撃記録の `targetId` が標的の射撃数 / 標的のHP減少から数えた命中数 (12 または 180 ごと。最後の1発は残りHPで止まるので切り上げ)。
- 「決着した弾の命中率」= 命中 / (標的向けの発射数 − 破壊の瞬間に飛翔中だった弾)。「発射基準」= 命中 / 標的向けの発射数 (飛翔中で破壊後に外れる弾を含む)。
- 「被弾 (破壊まで)」: 破壊した tick までの被弾回数と被ダメージ。撃った敵は、その弾の発射点 (`enemyFire` の銃口) で特定。

### 4.4 難しさの評価

- 制御砲台の遠隔破壊は **易しい寄り**: FCSで20発を当てるだけ (ロック 0.8秒 + 約2秒)、砲台の反撃は遅い (弾速 60 m/s、バースト 1.6秒周期) ので、掩蔽の陰から出入りすれば被害は 0〜数発。
  一方で「探し方」の難しさはあり、位置を誤ると (T03 の (311,0,89) など) 警備に囲まれて 3000 HP 超の被害になる。
- 脅威になるのは **警備ロボットの巡回と共有** (S03 の3体、S08 の G17/G18、S11 の G23)。特に S08 は広間の全域が巡回の視界に入り、掩蔽点を持つ歩いて着ける位置は北壁沿いの 2点だけだった (採用 (443,0,143): 被ダメージ平均 112・最大 360、もう一方 (455,0,143): 平均 972・最大 1510)。
- 弾薬は**やや厳しい**: マシンガンは 1体 27〜31発で、6体で 173発 (300発の 58%)。ミサイルは連射すると 3〜4発/体で 12発では 3〜4体分。補給がないので、制御砲台に使いすぎると他の戦闘の弾が足りなくなる (§5 の (3))。

1. **区画作り込み担当が報告した狙撃候補の一部は、制御砲台のFCS要件を満たさない**

   | 砲台 | 報告された領域 | 実測 |

   | T11 | S11 西壁沿いの凹み (86, 204..218) | 立てる 60/75 点の T11 までの距離が **121.6〜132.1 m。ロック可 0** (FCS射程 120 m の外。ビームも届かない)。(86,204) (86,211) (86,218) にプレイヤーを置くと、代わりに警備 G22 がロック候補になる |

   コメント (sectors/S03.ts, S08.ts, S11.ts) は「隔壁から」の距離と「砲台から」の距離を混同している。狙撃位置として機能する位置は自動探索で多数見つかる (上表)。
2. **砲台から見えないのにロックして一方的に撃てる位置がある** (敵AIの視線と、プレイヤーの銃口・カメラの位置の非対称)。
   敵の索敵は「敵の銃口 → プレイヤー中心の1点」の線分だけで判定する (`enemies.ts` の `enemyDecisionStep`)。一方プレイヤーの銃口は中心から前 1.25 m・右 1.05 m・上 0.75 m 突き出て、FCSは「カメラ」と「銃口」から砲台中心が見えればロックできる。
   そのため、遮蔽の角から銃口だけを出すと、**砲台は撃ち返さないのにこちらは補正射撃で撃てる** 位置ができる。60〜118 m でロックでき弾道が通る位置のうち、砲台が撃ち返さない位置は
   T03 50 / T07 80 / T08 11 / T11 27 / T14 119 / T15 23 か所 (撃ち返される位置は 688 / 896 / 1467 / 1583 / 1120 / 1983 か所)。
   再現: `npx tsx tools/turret-kill.ts --oneway` — 各砲台の1か所 (約90 m) から立ったままマシンガンで撃つと、**砲台は1発も撃たず (発射数 0)、3.54〜3.67秒で破壊** (被弾 0。T11 は警備 G23 から 4回/72 HP)。
   仕様違反ではない (§2.3 は「敵からプレイヤーまで」の遮蔽で判定) が、遠隔破壊の危険度をさらに下げている。直すなら敵の視線判定をプレイヤー箱の複数点 (または銃口) にする (敵AI担当) か、そのままにするかは設計判断。
3. **弾薬の配分**: マシンガンは 1体を 20発命中で倒すが、弾の飛翔時間 (0.8〜1.2秒 = 8〜12発分) の間に撃った分が余るため 27〜31発を使う。6体で 173発 (300発の 58%)。補給がないので残りは 127発。
   撃ち方の工夫 (命中数を数えて止める) で 20発/体に近づけられるが、通常のプレイでは余る。ミサイルは 3〜4発/体で 12発では 3〜4体分。バランスの材料として記録する。
4. **警備ロボットが狙撃位置の近くを巡回する区画** (S03 の G07/G08/G09、S08 の G17/G18、S11 の G23) では、静的に見つからない位置でも巡回・警戒の追跡で見つかる。
   掩蔽ボットは警備を撃ち返して対処したが、位置によっては被害が 1000〜数千 HP に達する (§3.1 の選定表)。難しさの調整をするなら、このあたりが効く。
