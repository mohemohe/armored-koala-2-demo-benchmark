LLMコーディングエージェントの総合的な実装能力を評価するためのベンチマーク課題です。

## 概要

**ARMORED KOALA 2 (AK2) DEMO** は、コアラの頭部を持つ戦闘ロボットを操作して廃工場から脱出する、TPS視点の高速メカアクションシューティングゲームです。  
[Three.js](https://threejs.org/)を使用してブラウザ上で動作する、実際にプレイ可能なゲームとして完成させることが求められます。

![sonnet-5.5の例](https://i.imgur.com/UU1xMhO.png)

### ゲーム内容

- **機体**: コアラの頭部を持つ装甲ロボット。2脚/4脚の選択、3種類のFCS、3種類のジェネレーターによる18通りの機体構成
- **武器**: マシンガン（重力付き実弾）、ビーム（即時命中）、ハンドミサイル（誘導弾）の3種を携行
- **移動**: 通常歩行、高速グライド、瞬間加速のクイックブースト（QB）、推進器による飛行
- **ステージ**: 15区画以上の大規模廃工場。分岐路、環状経路、高低差を含む複雑な構造
- **敵**: 警備ロボット30体＋固定砲台15体の計45体。偏差射撃と追跡行動を持つ独立AI
- **目標**: 6基の制御砲台を破壊して隔壁を開放し、最終搬出ゲートから脱出

## ベンチマークとしての評価観点

この課題は、単一のプロンプトからゲームを完成させる過程で、LLMコーディングエージェントの以下の能力を総合的に評価することを目的としています。

### 指示追従能力

仕様書には数百に及ぶ具体的な数値条件（速度、ダメージ、タイミング、距離など）と、明示的な禁止事項が記載されています。  
これらを正確に読み取り、一つも逸脱せずに実装へ反映する能力を測定します。  
「だいたい合っている」実装ではなく、仕様の字義どおりの挙動が求められます。

### 空間把握能力

15区画以上・最短移動距離1500m以上のステージを、分岐3箇所以上、環状経路2箇所以上、必須飛行箇所6箇所以上、3層以上の高度帯、60m×50m以上の戦闘区画5箇所以上という制約のもとで設計する必要があります。  
空間的に整合する3D構造を、テキスト指示のみから構築する能力を評価します。

### 状態管理能力

EN（エネルギー）の消費・回復・待機時間、QB（クイックブースト）の単発入力判定・噴射・慣性減速・自動グライド遷移、FCSのロック進捗・対象追跡・失効処理、敵AIの攻撃タイマー・警戒記憶・位置共有、一時停止時の全状態凍結と復帰、再出撃時の完全初期化など、相互に影響し合う多数の状態を矛盾なく管理する能力を測定します。

### 3Dモデリング能力

コアラの頭部（丸い耳、黒い鼻）を持つ装甲ロボットを、2脚・4脚で切り替え可能な立体モデルとしてコードで造形し、歩行アニメーションを付ける必要があります。  
外部モデルの読み込みは禁止されており、Three.jsのプリミティブのみで機械的な質感と生物的な特徴を両立させる能力を評価します。

### テストハーネス自作能力

仕様にはマシンガンの偏差・重力補正に対する13条件の必須命中試験（A01〜A13）が定義されており、各条件20発中20発の命中と残差0.01m以下が求められます。  
本編と同一の射撃・弾体・衝突処理を使用した試験環境を自ら構築し、定量的に検証する能力を測定します。  
また、`window.__AK2__.getSnapshot()` による読み取り専用の状態取得APIの実装も求められます。

### コンテキスト一貫性

仕様書（非公開）は約2万トークンに及び、序盤で定義した規則（例: QBの単発性、グライドのEN消費0、弾速のワールド座標系基準）が終盤の検証条件と整合する必要があります。  
文書全体を通じて矛盾のない実装を維持し、後半のセクションで前半の定義を上書きしたり忘れたりしない能力を評価します。

### 物理計算能力

マシンガンのFCS補正では、偏差射撃（移動予測）と重力落下を同時に考慮した4次方程式の求解が必要です。  
弾体は発射後に18m/s²の重力加速度を受け、等速直線運動する目標への到達時間を解析的または数値的に求めたうえで、射出方向を決定します。  
さらに、フレームレート非依存のシミュレーション、高速移動時のすり抜け防止、放物線軌道の衝突判定など、ゲーム物理の正確な実装が求められます。

## 使用ハーネス

- **OpenAI GPT系モデル**: [Codex](https://openai.com/ja-JP/codex/)
- **Anthropic Claude系モデル**: [Claude Code](https://claude.com/ja/product/claude-code)
- **その他のモデル**: [OpenCode](https://opencode.ai/ja)

### ベンチマーク実行方法

システムはサンドボックスで完全に分離し、各ハーネスのメモリが空の状態にします。  
[mise](https://mise.jdx.dev/) を使用し、ベンチマーク開始時点の `node@lts` 、 `npm@lts` および `playwright-cli` をインストール済みの環境で各ハーネスを実行します。  
`~/armored-koala-2-demo` のディレクトリで、各ハーネスに仕様書（**非公開**）のみをプロンプトとして渡します。

## ディレクトリ構成

各モデルの出力は、モデル名のディレクトリに格納されています。

```
├── README.md            # このファイル
├── fable-5.1/           # Claude Fable 5.1 の出力
├── fable-5.2/           # Claude Fable 5.2 の出力
├── gpt-6-astra/         # GPT-6 Astra の出力
├── gpt-6.1-sol/         # GPT-6.1 Sol の出力
├── gpt-6.2-astra/       # GPT-6.2 Astra の出力
├── opus-5.5/            # Claude Opus 5.5 の出力
├── sonnet-5.5/          # Claude Sonnet 5.5 の出力
└── ...
```

各ディレクトリ内のプロジェクトは以下のコマンドで起動できます:

```bash
cd <model-directory>
npm ci
npm run build
npm run dev -- --host 0.0.0.0 --port 5173
```
