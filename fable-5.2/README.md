# ARMORED KOALA 2 (AK2) DEMO

コアラの頭を持つ戦闘ロボットを操作し、廃工場から脱出する TPS 視点の高速メカアクションシューティングです。
TypeScript + Three.js（r187）+ Vite で実装しています。HUD とメニューは HTML/CSS です。
機体・敵・ステージ・テクスチャ・エフェクト・効果音は全てコードで生成しており、実行時に外部のリソースは取得しません。

要求仕様は [`docs/SPEC.md`](docs/SPEC.md)、モジュール構成は [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)、
ステージの設計と実測値は [`docs/STAGE.md`](docs/STAGE.md) にあります。

---

## 1. 起動手順

Node.js と npm が必要です（依存関係のバージョンは `package.json` で固定し、`package-lock.json` を同梱しています）。

```sh
npm ci                                        # 依存関係の導入
npm run build                                 # 型検査 (tsc --noEmit) + 本番ビルド (dist/)
npm run dev -- --host 0.0.0.0 --port 5173     # 開発サーバーで起動 → http://<ホスト>:5173/
```

- ビルド済みのものを確認する場合: `npm run preview -- --host 0.0.0.0 --port 4173`
- 開発サーバー・プレビューサーバーは、どのホスト名（IP、localhost、コンテナ名、転送 URL）で開いても応答します
  （`vite.config.ts` の `allowedHosts: true`）。
- 対象はデスクトップのキーボード＋マウスです。表示領域は 1280×720 以上を想定し、ウィンドウのリサイズに追従します。
  WebGL2 とポインターロックに対応したブラウザーが必要です。
- 乱数シード: URL クエリー `?seed=<32bit 符号なし整数>`（例 `http://localhost:5173/?seed=123`）。未指定・不正な値は `20260908`。
  同じシード・構成・入力なら進行を再現します。
- その他のコマンド: `npm test`（単体・結合テスト、vitest）、`npm run validate:stage`（ステージ検証）、
  `npm run report:stage`（`docs/STAGE.md` の再生成）。ブラウザーでの E2E は [`tools/e2e/README.md`](tools/e2e/README.md)。

## 2. ゲームの流れ

1. **格納庫** — 起動後に表示されます。FCS（3 種）・ジェネレーター（3 種）・脚部（2 種）を選び（18 構成）、
   各部品の長所・短所、脚部補正後の実効性能、武装、「操作方法」を確認して「出撃」を押します。
   脚部を変えると 3D モデルも 2 脚／4 脚に変わります。
2. **プレイ中** — 「出撃」のクリックでマウスカーソルを画面に固定（ポインターロック）して開始します。
3. **一時停止** — `Esc`、ポインターロックの喪失、ウィンドウのフォーカス喪失、タブの非表示化で一時停止します。
   「再開」「操作方法」「同じ構成で再出撃」「格納庫へ戻る」を選べます。
4. **クリア／失敗** — 6 基の制御砲台を全て破壊して最終搬出ゲートを開き、その先の脱出領域に入るとクリア。
   HP が 0 以下、またはステージ外への落下で失敗。結果画面から「同じ構成で再出撃」「格納庫へ戻る」を選べます。

ポインターロックを取得できなかった場合は、理由と再試行手段を表示し、ゲーム内の時間は進めません。
取得を待っている間は何も変化しません（再出撃の初期化も、ロックを取得した瞬間に行います）。

効果音は WebAudio による手続き生成です（音声ファイルなし、BGM なし）。音声出力（AudioContext）は、最初の
「出撃」のクリックの中で初めて作成します（「再開」「同じ構成で再出撃」「再試行」のクリックでも再開を試みます）。
ゲーム内の音が鳴るのはプレイ中だけで、一時停止・格納庫では止まり、クリア／失敗時は短い合図音だけが鳴ります。
`M` キーでいつでも ON / OFF（ミュート）を切り替えられます。WebAudio が使えない環境では無音のまま動作します。
**効果音は誰も実際に聴いて確認していません**（§8）。

## 3. 操作方法

| 操作 | 入力 | 挙動（2 脚での基準値） | EN 消費 |
| --- | --- | --- | --- |
| 通常移動 | `W` `A` `S` `D` | 10 m/s。カメラの水平方向が基準 | 0 |
| 視点・照準 | マウス移動 | TPS カメラの旋回 | 0 |
| ジャンプ | 接地中に `Space` | 上向き初速 10 m/s | 0 |
| グライドの切り替え | `Shift` を 1 回押す | 地上 22 m/s。押し続ける必要はない | 0 |
| ブレーキ | `左Ctrl` | グライド解除と慣性を伴う減速 | 0 |
| 飛行 | `Space` を 0.20 秒以上長押し | 空中水平移動 16 m/s、上昇 8 m/s | 20 EN/秒 |
| クイックブースト（QB） | `Q` を 1 回押す | 初速 80 m/s、噴射 0.15 秒、その後自動でグライドへ | 発動時に 36 EN を 1 回だけ |
| 射撃 | マウス左ボタン | 押している間、武器の射撃間隔で発射 | 武器による |
| 武器切り替え | `1` / `2` / `3` | マシンガン / ビーム / ハンドミサイル | 0 |
| 一時停止 | `Esc` | ポインターロック解除と一時停止 | 0 |
| 音声の ON / OFF | `M` | 効果音のミュートを切り替え（格納庫・プレイ中・一時停止・結果画面のどこでも有効） | — |

- **Q は単発入力**です。押し続けても QB は 1 回で、再発動には離して押し直します（再使用まで 1.00 秒）。
- **QB 後は自動でグライド**へ移行し、キーを全て離しても滑走を続けます。**グライドの EN 消費は 0** です。
  **止まるには `左Ctrl`（ブレーキ）か `Shift`（グライド解除）**を使います。
- **射撃は対象を FCS 領域（画面中央の円）内に保つだけ**です。ロック完了後は、偏差と重力落下を FCS が自動補正して
  実際の銃口から発射します。中央の照準を補正マーカーへ手動で合わせる必要はありません。
- 一時停止からの再開時、押したままのキー（Q を含む）は、いったん離して押し直すまで無効です。
- 「出撃」「再開」「再出撃」のクリックは射撃になりません。ダブルクリックの 2 回目も射撃になりません
  （その押下を 0.2 秒以上押し続けた場合だけ、引き金として扱います）。
- `左Ctrl` + `W` はブラウザーの「タブを閉じる」に当たるため、プレイ中は離脱の確認を出します。
- **飛行**: 地上で `Space` を押すとまずジャンプし、そのまま押し続けると 0.20 秒後から飛行します（20 EN/秒）。
  空中で押し直した場合も 0.20 秒後からです。EN 切れで着地したあとは、押したままでも浮き上がりません
  （地上から飛び立つには新しい押下が必要）。押したまま足場の端から外へ出た場合は、空中に出た時点で飛行に移ります。
- **音声**: `M` で ON / OFF。現在の状態は、格納庫の下部と一時停止メニューに「音声 ON [M]」／「音声 OFF [M]」と文字で
  表示し、切り替えたときは画面上部にも短く表示します（HUD のパネルや通知に重なる場合は、その下へ移動します）。
  選択はブラウザー（localStorage）に保存します。`左Ctrl`（ブレーキ）などの修飾キーを押している間は `M` は反応しません。
- 120 Hz を超える描画頻度（240 Hz など）では、シミュレーションの更新（1/120 秒）が 1 回も走らない描画フレームが
  あります。短いクリックやキーのタップは、少なくとも 1 回の更新に届くまで保持します（1 クリックで 1 発、
  `Q` 1 回で QB 1 回、`左Ctrl` の短いタップでもグライド解除）。

同じ内容は、格納庫と一時停止メニューの「操作方法」からゲーム内で参照できます。

### HUD

中央に FCS の判定円（実際の判定と同じ半径）と照準、左下に武器と残弾（ビームは「∞ 8 EN/射」）、右下に EN と
最大 EN・EN バー・QB の可否と残り時間・移動モード、下に HP と最大 HP・HP バー、左上に現在の区画・目標・進路、
右上に制御砲台の破壊数（0/6〜6/6）・隔壁 B1〜B6 の開閉・最終ゲートの状態を表示します。
ロック対象（現在位置）のマーカーと、実際の射出方向を示す補正照準マーカー（補正中／補正解なしを文字でも表示）は
別の形で表示します。敵の射撃予告と被弾方向も表示します。状態は色だけでなく文字・形でも区別します。
目標ピンと進路マーカーは、HUD のパネルに重なる位置ではパネルの手前の矢印表示に切り替わり、判定円の下のロック状態表示
（NO LOCK / LOCKING / LOCK ON）に重なる位置では文字を省いて印だけになります（距離は左上のパネルに常に表示）。
目標までの距離は、ロック対象の距離表示と同じく銃口からの距離です。

## 4. ステージ構成

舞台は一続きの廃工場（別ステージへの切り替えなし）です。以下の数値は、ステージ検証ツール
（`npm run validate:stage`：実際の衝突ボックスから計測）の出力で、詳細は `docs/STAGE.md` にあります。

- **19 区画**（7 種類の空間構成）: S01 搬入口（開始地点）→ S02 検問連絡路 → S03 資材ヤード → S04 圧延棟
  （→ S05 圧延制御室）→ S06 搬送縦坑 → S07 組立ライン（⇄ S18 部品搬送回廊）→ S08 検査棟 → S09 保守用配管区画 →
  S10 動力棟 → S11 冷却設備 → S12 排気縦坑 → S13 地下搬送区画 → S14 主製造ホール（⇄ S19 保守回廊）→
  S15 出荷倉庫 → S16 外周搬送路 → S17 搬出ゲート（脱出領域）。必須区画は 16。
- **正規クリアに必要な最短移動距離**: 証明済みの下限 2002 m（グリッド最短経路 2171 m、要求は 1500 m 以上）。
- **敵 45 体**: 警備ロボット 30 体（G01〜G30、HP 120）＋固定砲台 15 基（T01〜T15、HP 240）。16 区画に配置。
- **制御砲台 6 基**（固定砲台 15 基の内数、6 つの異なる区画）と対応する隔壁:
  T01（S03）→ B1、T04（S05）→ B2、T06（S07）→ B3、T08（S08）→ B4、T11（S11）→ B5、T14（S14）→ B6。
  6 基全ての破壊で最終搬出ゲートが開きます。残り 39 体の全滅は不要です。
- **飛行が必要な昇降箇所 7**（F1〜F7、宣言上の高低差 8〜14 m）、**分岐 4**（BR1〜BR4：短いが射線の多い経路と、
  長いが遮蔽された経路）、**環状経路 4**（LP1〜LP4）、広い戦闘空間 7、高度帯 11（−12 m〜+46 m）。
- 進行方向は、HUD 左上の「進路」行と画面上の進路マーカー（紫の二重シェブロン）、制御砲台は目標マーカー（ピン）と
  敵モデルの外観で識別できます。

## 5. 評価用インターフェース

`window.__AK2__.getSnapshot()` が、SPEC §10 の構造のスナップショット（毎回新しいコピー）を返します。

- `window.__AK2__` は凍結したオブジェクトで、メンバーは `getSnapshot` だけです。置き換え・追加・削除はできません。
- ゲームのページ（`/`、ビルド後の `index.html`）には、状態を変更するデバッグ機能・無敵化・自動クリア・デバッグ用の
  クエリーパラメーターはありません。ページが追加するグローバルは `__AK2__` だけです（開発サーバーでも同じ）。
- `dev/` 以下は部品単体の開発用ハーネス（`dev/hud.html`、`dev/mech.html` など）です。開発サーバーを起動すると
  `/dev/*.html` として開けますが、ゲームのページからは読み込まれず、本番ビルド（`npm run build`）にも含まれません。
  これらのページはそれぞれ独立した試験用のシミュレーションを持ち、自分のテストスクリプト用のグローバル
  （`__hud` など）を定義しますが、ゲーム本体の状態には触れられません。`dev/app-test.html` は本体と同じ `App` を
  小さな試験用ステージで動かすページで、追加のグローバルはありません。

## 6. 検証

実施環境: Linux、Node.js 26、headless Chromium（playwright-core、WebGL は SwiftShader によるソフトウェア描画）。
**実機の GPU・実際のマウスとポインターロックを備えた通常のブラウザーでは確認していません**（§8）。
ソフトウェア描画ではプレイ中のフレームが 0.25 秒を超えることが多いため、ブラウザーでの計測は全てゲーム内時間
（`elapsedSeconds`）基準で行い、一部はテスト側で注入した仮想フレーム時計を使っています（ゲームのページ自体は無改造）。

### 6.1 FCS 補正試験（SPEC §4.6）

方法: `tests/fcs.test.ts`（`npx vitest run tests/fcs.test.ts`）。**本編と同じシミュレーションコード**（`src/sim` の
ロック処理・射撃解・弾体・連続衝突判定）を Node 上で動かし、遮蔽物のない試験配置で銃口を m = (0, 20, 0)、
半径 0.5 m の標的を p = m + r に置き、FCS の通常のロック完了を経て 1 発ずつ発射し、**実際の弾体が実際の当たり判定に
命中したか**を数えています（数式だけの検証ではありません）。各回で標的と射撃状態を初期化し、18 構成を巡回しています。
ブラウザー経由（描画・入力込み）では A01〜A13 の配置は試験していません。

- 残差は「記録された銃口・初速度・重力から求めた弾の位置」と「等速予測した標的中心」の、採用時刻における距離です。
- 発射速度の大きさは 100 m/s（誤差 1.4e-14 以下）。A03・A05 の到達時間と初速度、A13 の到達時間は、仕様の参考値と相対誤差 1e-6 未満で一致しました。
- 標的半径を 0.01 m にした同じ 13 条件でも 13/13 命中（弾道が予測中心の 0.01 m 以内を通過）。
- ビーム: 同じ 13 配置 × 6 構成で 78/78、発射時点の現在位置へ即時命中（到達時間 0、残差 0）。
- ミサイル: A05・A06・A07 × 6 構成で 18/18 命中。初期方向は弾速 45 m/s の偏差方向、旋回率の最大は 120.0°/秒（上限 120）。
- 自機のグライド・飛行・QB 噴射中（A05 の r と v、各 6 構成）: 6/6・6/6・6/6 命中。弾は実際の銃口位置から初速 100 m/s
  ちょうどで発射され、自機速度（最大 80 m/s）は加算されていません。
- マシンガンの弾道は補正後も放物線（閉形式との差 0）、発射後に急変針した標的には命中しません（最接近 15.9 m、追尾なし）。
- 各条件の 20 発のうち 2 発は、ロックが完了したその更新内で発射しています（残りは完了の 1〜23 更新後）。
- ロック所要時間: 出撃の最初の瞬間から円内にある対象は、18 構成の全てで出撃からちょうど所要時間後
  （1.2 / 0.8 / 0.5333 / 0.4 / 0.2667 秒）にロック完了（ロックは t = 0 でも判定）。FCS 3 種 × 脚部 2 種については
  30・60・144 fps のフレーム駆動でも同じ時刻に完了し、押し続けたミサイルはその瞬間に発射されました。
- 120 m の境界: 発射時点で銃口からちょうど 120 m にあり遠ざかる標的に 12 発、12 発ともロックを維持して命中。
  シミュレーションが保持する距離は位置更新の丸めで 120 m から最大 2.4e-13 m ずれるため、判定には 1e-9 m（1 nm）の
  丸め許容だけを設けています。120 m + 2 nm 以遠の対象は取得しません（ミサイルも発射拒否）。
- リサイズ: 更新が走っていない一時停止中に表示領域を変えても、新しい判定円の外になった対象のロックと補正解は

    （Node、`tests/stage.test.ts`）。
- `npm ci`・`npm run build`・`npm run dev -- --host 0.0.0.0 --port <port>`（プロジェクトのクリーンコピーで `npm ci` と `npm run build` が終了コード 0、成果物は index.html＋JS 1＋CSS 1。`npm run dev`・ビルド・プレビューは `delivery.mjs` で確認）

## 8. 未確認項目

- **実機の GPU を持つ通常のブラウザー、実際のマウス、実際のポインターロックでの動作**。確認は全て headless Chromium
  （ソフトウェア描画、ポインターロックはブラウザーのエミュレーションまたはテスト側の代替）です。特に次の点は未確認です:
  実際の `Esc` の挙動（ブラウザーがキーを消費しロック喪失だけが届く）、`Esc` 直後 1〜2 秒はブラウザーが再ロックを拒否する
  こと（その場合は説明と再試行が出る想定）、実際のウィンドウ切り替え・タブ切り替え、`Ctrl+W` の確認ダイアログそのもの。
- **実際の 30 / 60 / 120 fps での描画**。フレーム頻度に依存しないことは、シミュレーションへ与えるフレーム時間を変えて確認しています。
- **本番ステージ（廃工場）を、人が、ブラウザー自身のポインターロックと実時間のフレームで最後までクリアすること**。
  ブラウザーで本番ステージを出撃からクリアまで通したのは `factory-run.mjs`（§6.4）の 1 回だけで、テスト側のボットが
  実際のキー・マウス入力を送り、ポインターロックはテスト側の代替、時間は仮想フレーム時計（1 フレーム＝ゲーム内 1/15 秒）、
  表示は 320×180 という条件です。しかも **その実行は最終修正（警備ロボットの側方移動、T04 の射撃位置の経路点、HUD、
  エフェクト）より前のビルドでのもの**で、修正後のビルドではブラウザーでの完走を再実行していません（同じボットの
  Node 上での実行と、ステージ検証ツール V14・V16 だけ）。QB・グライド・ブレーキは本番ステージの入力経路では使っておらず、
  迂回路と S18・S19 は通っていません。
  `spec-verify.mjs`（§6.4）が最終ビルドの本番ステージで実際の入力により確認したのは、1 基目（T01）の撃破と隔壁 B1 の開放までです。
- **動いている画面での見え方**。マシンガンの曳光・ミサイルの噴射と煙・HUD のマーカーは、1280×720 の静止画（スクリーンショット）で
  確認しただけです。60 fps で動いている状態でのちらつき、曳光の追いやすさ、マーカーの揺れは未確認です。
  HUD の重なりの確認（§7）は開発用ハーネス `dev/hud.html`（本番と同じ `Hud` クラス、平坦な試験用ステージ、状態は強制設定）で
  カメラの向きを機械的に振って DOM の矩形を調べたもので、本番ステージを実際にプレイしながらの網羅的な確認ではありません。
- `spec-verify.mjs` のブラウザー側実測（§6.2・§6.4）で**確認できなかったもの**:
  - §4.6 の A01〜A13 の配置そのもの（ブラウザーでは実ステージの砲台・警備ロボットへの射撃を照合。A01〜A13 は Node 試験）。
  - 120 m を超えた対象でのロック解除。試験用ステージの最長の見通しは 113 m で、本番ステージでは該当する位置まで操作していません
    （120 m の境界は Node 試験 `tests/fcs.test.ts`）。
  - ミサイルの発射後の誘導（旋回上限 120°/秒、再照準、遮蔽中の記憶）と、敵弾・自弾の飛行中の軌道。スナップショットに弾体が
    含まれないため、ブラウザーからは発射記録と命中時刻（HP の変化）でしか観測できません。
  - 敵の偏差射撃の精度。ブラウザーでは「静止した自機への命中」と発砲時刻だけを計測し、移動する自機への偏差は切り分けていません（Node 試験）。
  - 実際のフォーカス喪失とタブ非表示。headless Chromium では別タブを前面に出しても blur / visibilitychange が発生せず、
    スクリプトから発火させた模擬イベントでの確認です。
  - 「代替ロック」の行は、ポインターロック API の代替と仮想フレーム時計をテスト側から注入した条件での値です（入力は実イベント、
    ページは無改造）。実フレーム時間・ブラウザー自身のロックで計測したのは「実ロック」と書いた行（単発入力、一時停止）だけです。
- Chromium 以外のブラウザー（Firefox、Safari）。
- ダブルクリックの 2 回目を射撃にしない処理は、ブラウザーが 2 回目の押下に付ける `MouseEvent.detail`（2 以上）に依存します。
  実際のマウスのダブルクリックでは未確認です（テストでは `detail` を指定した入力で確認）。
- 見た目（造形、明るさ、エフェクトの強さ）の評価は、headless Chromium のスクリーンショットによる目視だけです。
- **効果音を実際に耳で聴く確認は、誰も行っていません**（この環境には音声出力装置がありません）。確認したのは、
  音源が開始されること・出力サンプルの有無と大きさ・一時停止やミュートで 0 になること、および音響エンジン単体の
  オフライン計測（`tests/audio.test.ts`、`dev/audio.html`）だけです。音色、音量のバランス、左右の定位、連射時に
  耳障りでないかは未確認です。
- 実際のブラウザーの自動再生制限（ユーザー操作なしで作った AudioContext が停止状態になる挙動）のもとでの動作は
  未確認です。確認したのは「最初の出撃クリックのイベント内でだけ AudioContext を作る」ことと、停止状態のまま再開を
  拒否する AudioContext をテスト側で注入してもゲームが動くことです。Chromium 以外のブラウザーでの音の動作も未確認です。
- 実際の 240 Hz などの高リフレッシュレート表示での入力（確認は、フレーム時間を与える単体テストと仮想フレーム時計）。

## 9. 既知の問題

- **BGM はありません。** 効果音（任意要件）は接続済みですが、誰も実際に聴いて確認していません（§8）。
  気になる場合は `M` でミュートできます。
- 1 フレームが 0.1 秒を超える低い描画頻度（10 fps 未満）では、フレームより短い 1 回のクリックでも、そのフレームが進める
  ゲーム内時間（最大 0.25 秒）の間は引き金を引いたものとして扱うため、マシンガンが 2〜3 発出ます
  （計測: 10 fps 以上は 1 発、5〜9 fps で 2 発、4 fps で 3 発）。
- 1280×720 より小さい表示領域では HUD のパネル同士が重なります（対象外のサイズ）。
- ソフトウェア描画など非常に低いフレーム頻度では、1 フレームに進めるゲーム内時間を 0.25 秒までに制限しているため、
  ゲームがスローモーションになります（物理・命中の結果は変わりません）。
- ポインターロックの要求にブラウザーが 2.5 秒以内に応答しない場合は失敗として扱い、再試行を促します。
  その後に遅れて届いたロックは解放します。
- 4 脚の脚先は当たり判定の箱（2.6 × 4.0 × 2.6 m）より外側に出るため、壁際では脚が壁にめり込んで見えることがあります。
- 急角度（下向き 40° 以上）で照準すると、武器の後端が右耳や肩装甲に重なって見えることがあります。
- **追従カメラと自機の間に床の縁や設備が入り、自機が隠れることがあります。** カメラの位置決めは「機体上方の支点からカメラまで」の
  直線だけを衝突判定しており（この位置はロック判定にも使うシミュレーションの一部なので、最終段階では変更していません）、
  カメラが自機より高い床の上や背の高い設備の向こう側に出ると、その縁が自機を隠します。計測（Node、経路点 106 か所で次の経路点の
  方向を向く）で該当したのは 1 か所: 隔壁 B1 の張り出しから圧延棟の床へ降りた直後の経路点 (194, 6, 84) で、進行方向（南東）を
  向くとカメラが張り出しの上に出て自機が完全に隠れます（18 標本点中 0）。視点を少し回すか数 m 進むと解消します。
  圧延制御室（S05）の継電器盤（高さ 5 m）の北側 4 m 以内に立って T04 を狙う場合も同様です（経路の射撃位置は盤から 6 m 離しました）。
  真正面・至近距離（約 10 m 以内）のロック対象が自機の頭部に隠れる点も同じ構図によるものです。
  壁際で真上近くを見上げるとカメラが機体のすぐ後ろまで寄り、自機の頭部が画面の下 1/3 ほどを占めます（標的は見えます）。
- **自機の弾は自機越しに描画します。** 追従カメラは射線の真後ろにあるため、銃口から照準付近の標的までの画面上の弾道の大半
  （1280×720・標的 37 m で約 8 割）が自機の頭と肩に重なります。マシンガンの曳光とミサイルの噴射炎は、自機に隠れる部分だけ
  明るさ 70 % で自機の上に重ねて描いています（壁・床・他の物体には通常どおり隠れ、敵弾は透過しません）。
  ミサイルの弾体と煙は透過させていないため、発射後 約 0.3 秒は噴射炎だけが見えます。
- 狭い隙間越しに自機が見えている警備ロボットは、6 m/s で短く横へ動いたあと最長 1 秒ほどその場で撃ち続けてから折り返します
  （1.5 秒より短い間隔で反転しないための仕様。側方へ動ける幅が 3.5 m 未満の場所では動かずに撃ちます）。
- 検査棟の制御砲台 T08 の周囲の床に描いた隔壁番号「B4」4 枚は、経路が到達する側（床開口の南縁）から正立して読める向きに
  揃えてあります。反対側から見ると逆さに見えます。
- 開発用ハーネス（`dev/`）とテストだけが使う読み取り・描画専用のメソッド（`GameRenderer.setDebugCamera` /
  `debugProjectWithThree` / `getStageView` / `setResolutionGovernor` / `getDebugInfo`、`AudioEngine.getMixer` / `getDebugInfo`）が
  本番ビルドのコードにも含まれています。ページからは到達できず（公開しているのは凍結した `window.__AK2__.getSnapshot` だけで、
  `App` もレンダラーもグローバルに出していません）、出荷コードからの呼び出しはなく、いずれもシミュレーションの状態を変更しません
  （`setDebugCamera` は描画カメラだけを差し替え、HUD の投影とロック判定には影響しません）。ハーネスと単体テスト 30 か所以上が
  参照しているため、最終段階での移設は見送りました。

src/ui/               HUD、格納庫、メニュー、操作説明（HTML/CSS）
src/input/            キーボード・マウス入力、ポインターロック

tools/                ステージ検証・レポート、スクリーンショット、tools/e2e/（ブラウザー E2E）
dev/                  部品単体の開発用ハーネスページ（出荷ページからは読み込まれない）
docs/                 SPEC.md（要求仕様）、ARCHITECTURE.md、STAGE.md
